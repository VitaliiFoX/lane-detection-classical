# Виявлення смуг розмітки — правила роботи для ШІ-асистентів

STEM-проєкт з дисципліни «Комп'ютерна графіка та візуалізація». Команда з двох
людей: **Фояк Віталій** і **Сивопляс Максим**. Кожен працює зі своїм
ШІ-асистентом. Ціль проєкту — самі алгоритми обробки зображень і їх порівняння,
а не готовий продукт.

Перед роботою прочитай:

- [PLAN.md](PLAN.md) — задачі, власники, залежності, критерії готовності;
- [docs/pipelines.md](docs/pipelines.md) — точна специфікація 4 пайплайнів і
  параметрів;
- [docs/metrics.md](docs/metrics.md) — метрики, еталонні сценарії, пороги;
- [ARCHITECTURE.md](ARCHITECTURE.md) — модулі, контракти даних;
- [ADR.md](ADR.md) — чому зроблено саме так (не переглядай рішення без
  нового запису);
- `AGENTS.md` у теці, де редагуєш файл.

## Як організовані інструкції

`AGENTS.md` — єдине джерело правил: його читають Claude Code, Codex і
Antigravity. `CLAUDE.md` поруч — заглушка, що імпортує `AGENTS.md`. Тека з
власними обмеженнями має свій `AGENTS.md`; цей кореневий файл там не
повторюється. Нове правило клади в `AGENTS.md`, найближчий до коду, якого воно
стосується.

## Жорсткі правила (з методички — порушення коштує балів)

1. **Усі алгоритми обробки пишемо вручну.** Заборонено в `lanes/`, `tools/`,
   `main.py`: OpenCV (`cv2`), scikit-image, SciPy (`scipy.ndimage`,
   `scipy.signal`), Pillow `ImageFilter` / `ImageOps` / `ImageEnhance` /
   `Image.transform` / `resize` для обробки. Pillow — лише відкрити, зберегти,
   перетворити режим на RGB і **малювати** (`ImageDraw`) маски та лінії.
2. **Ніякого ШІ та машинного навчання** в алгоритмах: без нейромереж, k-means,
   scikit-learn. RANSAC теж не використовуємо — його немає в ТЗ.
3. **NumPy дозволено** як мову масивів: арифметика, `np.pad`, `np.cumsum`,
   `np.bincount`, `np.add.at`, `np.lib.stride_tricks.sliding_window_view`,
   `np.linalg.solve`, `np.polyfit`. Сам алгоритм (згортка, Оцу, Хаф, …) має
   бути видимим у нашому коді, а не схованим в одному виклику бібліотеки.
4. **Методи ЛР 5–6 не є самостійними стадіями.** Середнє, гаусове, медіанне,
   мін/макс-згладжування заборонені як стадія пайплайна. Викладачка дозволила
   лише гаусове згладжування всередині Кенні й мін/макс усередині top-hat.
5. **Жодних чисел у коді для параметрів методів.** Пороги, розміри вікон,
   коефіцієнти — у `config.json`, ключі описано в `docs/pipelines.md`.
   Випадковість — тільки з `seed` з конфігурації.
6. **Кожен метод має автотест** на зображенні 3×3 або 5×5, очікуваний
   результат якого пораховано вручну. Розрахунок пиши коментарем у тесті.
7. **Код має бути зрозумілим на захисті.** Власник файлу відповідає на питання
   про кожен рядок. Простий явний код важливіший за коротший чи швидший.
   Векторизація NumPy — так, але з коментарем, що саме вона рахує.
8. **Пиши тільки у файли свого власника** (таблиця нижче). Спільний файл
   змінюй лише в межах своєї задачі з `PLAN.md`.
9. **Використання ШІ декларується.** Після кожної задачі додай рядок у
   [META-USAGE.md](META-USAGE.md). Недекларований згенерований код — порушення
   доброчесності (множник M = 0,5).
10. **Фото CULane і результати не потрапляють у git** (ліцензія забороняє
    поширювати набір). Комітимо лише `data/sample.csv`.

## Команди

Інтерпретатор — з `.venv`: `.venv/bin/python` (macOS/Linux) або
`.venv\Scripts\python.exe` (Windows). Нижче `python` означає його.

```bash
python -m pip install -r requirements.txt

python -m pytest                                   # усі тести
python -m pylint lanes tools tests main.py         # має бути 10.00/10, 0 повідомлень

python main.py run --pipeline p1 --limit 10        # пілот на 10 фото
python main.py run --pipeline all                  # уся вибірка, усі пайплайни
python main.py report                              # summary.csv і графіки
python main.py check                               # еталонні сценарії (критерій C1)

python -m tools.make_sample                         # зібрати 100 фото з CULane
```

## Як виконувати задачу з PLAN.md

1. `git pull --rebase`.
2. Візьми першу незакриту задачу **свого** розділу в `PLAN.md`, у якої всі
   залежності закриті. Якщо такої немає — скажи людині, на що чекаєш.
3. Прочитай специфікацію задачі в `docs/` і `AGENTS.md` теки.
4. Реалізуй функції, сигнатури яких уже є в заготовці. **Не змінюй сигнатуру**
   спільного контракту без запису в `ADR.md` і попередження команди.
5. Докстрінг українською до кожної публічної функції: що робить, формули,
   типи й форми масивів. Коментар до кожного нетривіального кроку.
6. Тести: ручний розрахунок 3×3/5×5 + крайній випадок (порожнє чи однотонне
   зображення).
7. `python -m pytest` і `python -m pylint lanes tools tests main.py` — зелено,
   10.00/10.
8. Познач задачу `[x]` у `PLAN.md`, онови статус у `README.md`, якщо закрито
   етап, додай рядок у `META-USAGE.md`.
9. Один коміт на задачу, від імені людини, Conventional Commits українською:
   `feat: фільтр Собеля (F7)`, `test: …`, `fix: …`, `docs: …`.
10. `git push` — лише коли людина дозволила.

## Конвенції коду

- Python ≥ 3.10, лише залежності з `requirements.txt`.
- Ідентифікатори англійською, докстрінги й коментарі українською.
- Масиви: кольорове фото `np.uint8` форми `(H, W, 3)` RGB; сіре —
  `np.float64` `(H, W)` у діапазоні 0…255; бінарна маска — `np.bool_` `(H, W)`.
  Смуга — `np.ndarray` форми `(N, 2)` з точками `(x, y)` у пікселях фото.
- Методи — чисті функції: не читають файли, не друкують, не змінюють вхідні
  масиви. Параметри приходять аргументами, а не з глобального конфігу.
- На крайніх входах (однотонне фото, порожня маска, 1×1) метод не падає:
  повертає порожній результат. Помилку читання файлу кидає лише `io_utils`.
- Не глуши попередження pylint коментарями `# pylint: disable` — виправ код.

## Тести

- Детерміновані: фіксовані масиви або `synthetic.py` з `seed`.
- Не послаблюй перевірку, щоб тест став зеленим. Якщо тест падає — або код
  неправильний, або очікування; напиши, що саме, у коміті.
- Тест пайплайна запускає його на синтетичному кадрі й перевіряє відхилення
  знайдених смуг від відомих (`checks.mean_lane_offset`).
