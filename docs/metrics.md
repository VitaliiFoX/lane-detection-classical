# Метрики, еталони й пороги

## Що з чим порівнюємо

Метрики рахуємо **не між оригінальним і обробленим фото**, а між двома
чорно-білими масками однакового розміру:

- **еталонна** — смуги з ручної розмітки CULane (`.lines.txt`), намальовані
  лініями товщиною `masks.thickness` (16 px);
- **знайдена** — смуги, які повернув пайплайн, намальовані так само.

Маски `np.uint8` зі значеннями 0 і 255. Малює їх `lanes/draw.py`.

## Формули (`lanes/metrics.py`, власник Фояк)

```
MSE  = (1 / N) · Σ (I(i) − K(i))²
PSNR = 10 · log10(255² / MSE)          # MSE = 0 → metrics.psnr_cap (100 дБ)
SSIM = середнє по вікнах w × w:
       ((2·μx·μy + C1)(2·σxy + C2)) / ((μx² + μy² + C1)(σx² + σy² + C2))
       C1 = (k1·255)², C2 = (k2·255)², w = metrics.ssim_window
IoU  = |A ∩ B| / |A ∪ B|               # обидві порожні → 1.0
```

Для двох масок 0/255 `MSE = p · 255²`, де `p` — частка пікселів, що не
збіглися, тож `PSNR = 10 · log10(1 / p)`. Звідси поріг ТЗ: PSNR ≥ 15 дБ
означає не більше 3,2 % хибних пікселів, і `MSE ≤ 2056` — той самий поріг.

**Пастка.** Смуги займають кілька відсотків кадру, тож порожня маска теж має
непоганий PSNR. Груба оцінка: 4 смуги × ~320 рядків × ~20 px ≈ 2,6 % кадру
1640 × 590, тобто PSNR порожньої маски ≈ 16 дБ — **вище порогу ТЗ 15 дБ**.
SSIM порожньої маски теж високий, бо більшість вікон чорні в обох масках.
Тому:

- рядок `p0` (порожня маска) — базова лінія в кожній таблиці;
- у сценарії `normal_group` пайплайн мусить бути ще й кращим за `p0`;
- IoU порожньої маски дорівнює 0, тож IoU — головна метрика для висновків;
- у пілоті (T1) першим ділом рахуємо реальний PSNR і SSIM для `p0`. Якщо
  оцінка підтвердиться, пропонуємо викладачці поріг відносно `p0` або поріг
  IoU (так і було обумовлено в ТЗ: «уточнимо після перших запусків»).

## Відхилення від еталонних ліній (`lanes/checks.py`, власник Максим)

`mean_lane_offset(gt_lanes, pred_lanes, ys)` — для кожної еталонної смуги
знаходимо найближчу знайдену (за середнім `|Δx|` на рівнях `ys`) і
усереднюємо `|Δx|` по всіх еталонних смугах. Якщо знайдених смуг менше, ніж
еталонних, або котрась не перетинає рівень `y`, відхилення дорівнює `inf`.
`x` на рівні `y` беремо лінійною інтерполяцією по точках смуги.

Рівні `ys` задає `checks.offset_levels` — частки висоти кадру (за
замовчуванням 0,6; 0,7; 0,8; 0,9), тобто `ys = частка · (H − 1)`. Вони лежать
нижче горизонту синтетичного кадру (0,5) і вище нижньої межі трапеції p3
(0,95), тож кожен пайплайн має там точки смуг. Тести пайплайнів беруть ті
самі рівні.

## Еталонні сценарії (критерій C1)

Погоджено в ТЗ. `python main.py check` проганяє кожен пайплайн p1–p4 по
кожному сценарію і пише `results/c1_check.csv` зі стовпцями
`pipeline, scenario, value, threshold, passed`.

| Сценарій | Еталон | Критерій | Ключ конфігурації |
|---|---|---|---|
| `synthetic_straight` | синтетичний кадр, 2 прямі смуги | відхилення ≤ 5 px | `checks.offset_max_px`, `checks.offset_levels` |
| `synthetic_dark` | той самий кадр, яскравість × 0,4 | відхилення ≤ 5 px | `checks.dark_brightness` |
| `synthetic_noise` | той самий кадр, гаусів шум σ = 20, `seed` | відхилення ≤ 5 px | `checks.noise_sigma` |
| `normal_group` | 20 фото групи «звичайна дорога», ручна розмітка CULane | середні PSNR ≥ 15 дБ і SSIM ≥ 0,60, **і обидва вищі, ніж у p0** на тих самих фото | `checks.psnr_min`, `checks.ssim_min` |

4 сценарії × 4 пайплайни = 16 тест-кейсів. Частка пройдених і є оцінка C1.

У синтетичних сценаріях `value` — відхилення в пікселях (`inf`, якщо
пайплайн знайшов менше смуг, ніж є, або впав). У `normal_group` у `value`
записано обидва середні (`psnr=…; ssim=…`), а в `threshold` — пороги й
значення `p0`. Поки немає `results/metrics.csv` (ще не було `main.py run`),
рядки `normal_group` мають `value` «немає даних» і `passed = False`.
Якщо пайплайн не проходить сценарій (наприклад, p1 у темряві), **поріг не
знижуємо**: це результат для обговорення у звіті. Пороги можна змінити лише
після пілоту (T1) і з повідомленням викладачці.

## Файли результатів

`results/metrics.csv` — один рядок на (пайплайн, фото):

| Стовпець | Зміст |
|---|---|
| `pipeline` | `p0`…`p4` |
| `group` | `normal`, `crowd`, `shadow`, `curve`, `night` |
| `image` | шлях фото відносно `data/sample` |
| `mse`, `psnr`, `ssim`, `iou` | метрики масок |
| `lanes_found`, `lanes_gt` | кількість знайдених і еталонних смуг |
| `time_ms` | час роботи пайплайна на фото |

`results/summary.csv` (`main.py report`, власник Максим) — середні значення
метрик і часу для кожної пари (пайплайн, група) плюс рядок «усі групи»
(`group = all`). Стовпці: `pipeline, group, images, mse, psnr, ssim, iou,
time_ms`; `images` — скільки фото усереднено. Рядки `metrics.csv` без метрик
(фото не прочиталося, пайплайн упав) у середнє не входять.

Графіки — `results/figures/`:

- `iou_by_group.png`, `psnr_by_group.png`, `ssim_by_group.png`,
  `time_by_group.png` — стовпчикові діаграми за групами, стовпчик на кожен
  пайплайн;
- `examples_<пайплайн>.png` — сітка прикладів «фото → стадії → результат»:
  рядок на групу, перше фото групи зі збережених раннером стадій.
