# Підготовка до захисту — Фояк Віталій

Моя зона: пайплайни **p1 «Колір»** і **p2 «Оцу»**, їхні методи (HSV,
Собель, вирівнювання гістограми, Оцу), перетворення Хафа (спільне з p4,
ADR-0006), а також спільні модулі `filters` (кореляція з ядром), `io_utils`,
`draw` (маски), `metrics`, `runner`, `main.py` і `tools/make_sample.py`.

**Про числа.** Усі числа — з повного прогону на 100 фото CULane
(`results/summary.csv`, `results/c1_check.csv`) і з журналу підбору
`docs/experiments.md`. Значення параметрів — актуальні з `config.json`.

## 1. Методи

### Кореляція з ядром (`lanes/filters.py:9`, спільна)

**Ідея.** Нове значення пікселя — зважена сума його околу.

```
result[y, x] = Σ kernel[i, j] · image[y + i − r, x + j − r],   r = size // 2
```

Ядро не перевертаємо (це кореляція; для симетричних ядер те саме, що
згортка). Краї доповнюємо повтором крайніх пікселів (`np.pad(mode="edge")`),
тож результат того самого розміру. Ядро має бути квадратним і непарним,
інакше `ValueError`. Замість подвійного циклу по пікселях цикл іде по
комірках ядра (9 для 3×3): додаємо зсунуті копії зображення, помножені на
вагу, — так швидко й без OpenCV.

### p1, стадія 1 — колірна маска в HSV (`lanes/methods/color.py`)

**Ідея.** Розмітка — біла або жовта фарба; у HSV колір і яскравість
розділені, тож «білий» = мало кольору + світлий.

`rgb_to_hsv` (рядок 20), канали в 0…1:

```
V = max(R, G, B),   S = (max − min) / max   (max = 0 → S = 0)
δ = max − min;  якщо max = R: H = 60·((G − B)/δ mod 6)
                якщо max = G: H = 60·((B − R)/δ + 2)
                якщо max = B: H = 60·((R − G)/δ + 4)        (δ = 0 → H = 0)
```

`white_yellow_mask` (рядки 63–66):

| Параметр | Значення | Що робить і чому таке |
|---|---|---|
| `white_s_max` | 0,20 | максимум насиченості білого: біле майже без кольору; 0,1 губив фарбу з відтінком |
| `white_v_min` | 0,55 | мінімум яскравості білого. У ТЗ було 0,75 — на CULane стерта фарба темніша; на 20 фото IoU 0,166 проти 0,115. Нижче 0,45 у маску лізе асфальт |
| `yellow_h_min`…`yellow_h_max` | 35°…65° | відтінок жовтого (чистий жовтий — 60°) |
| `yellow_s_min`, `yellow_v_min` | 0,35; 0,50 | жовте насичене й не темне. На вибірці жовтої фарби майже немає — не підбирали |

### p1, стадія 2 — фільтр Собеля (`lanes/methods/sobel.py`)

**Ідея.** Похідна яскравості: де вона велика — контур.

```
      | −1 0 1 |
Gx =  | −2 0 2 |   (рядок 13),   Gy = Gxᵀ,   |∇| = √(Gx² + Gy²)  (np.hypot, рядок 28)
      | −1 0 1 |
```

Вага 2 у центрі — це похідна по x і водночас згладжування по y. Маску p1
(bool) подаємо як зображення 0/255 (`p1_color.py:29`), лишаємо
`|∇| > sobel_threshold · max` (рядок 30, `sobel_threshold = 0,3`) і
накладаємо ROI (рядок 31). Поріг майже не впливає: маска бінарна, тож усі
контури однаково сильні (0,1 і 0,3 дали той самий IoU).

### p2, стадія 1 — вирівнювання гістограми (`lanes/methods/histogram.py`)

**Ідея.** Розтягнути яскравості так, щоб кожен рівень зустрічався приблизно
однаково часто — темний кадр стає контрастним.

Сіре `Y = 0,299·R + 0,587·G + 0,114·B` (`color.py:10`, стандарт BT.601: око
найчутливіше до зеленого). Потім:

```
cdf(v) = кількість пікселів з яскравістю ≤ v        (рядок 23, np.cumsum)
v' = round( (cdf(v) − cdf_min) / (N − cdf_min) · 255 )   (рядок 32, таблиця lookup)
```

Однотонне фото повертаємо без змін — інакше ділення на нуль.

### p2, стадія 2 — поріг Оцу (`lanes/methods/threshold.py`)

**Ідея.** Перебрати всі пороги й узяти той, що найкраще ділить гістограму на
два класи.

```
σ²_B(t) = ω₀(t) · ω₁(t) · (μ₀(t) − μ₁(t))²     (рядок 37)
```

`ω₀, ω₁` — частки темного й світлого класів, `μ₀, μ₁` — їхні середні.
Максимум `σ²_B` = мінімум дисперсії всередині класів. Рахуємо за 256
кумулятивними сумами без циклу. Гістограма — лише по пікселях ROI
(`p2_otsu.py:30`). `otsu_iterations = 2`: друга ітерація ділить уже світлий
клас (рядок 62, `binary = candidates & (levels > threshold)`), бо розмітка
— лише ~3 % кадру й одна ітерація відділяє весь світлий асфальт. На 20 фото
IoU: 1 ітерація — 0,109, **2 — 0,139**, 3 — 0,126, 4 — 0,124.

### p1, p2 стадія 3 — перетворення Хафа (`lanes/methods/hough.py`, спільне з p4)

**Ідея.** Кожен білий піксель «голосує» за всі прямі, що через нього
проходять; пряма з найбільшою кількістю голосів — знайдена лінія.

```
ρ = x · cos θ + y · sin θ,   θ ∈ [−90°, 90°)          (рядки 28, 45)
x = (ρ − y · sin θ) / cos θ                             (рядок 95)
```

| Параметр | Значення | Що робить |
|---|---|---|
| `rho_step`, `theta_step_deg` | 1 px, 1° | крок сітки акумулятора |
| `min_angle_deg` | 10° | кут до горизонталі менший — не голосує (тіні, бампери, стоп-лінії). Було 20°: еталонні смуги пологі, медіана 26°, чверть — менше 14° |
| `max_lanes` | 4 | CULane розмічає до 4 смуг |
| `min_votes` | 40 | слабший пік — не лінія |
| `suppress_rho`, `suppress_theta_deg` | 20 px, 5° | після піка обнуляємо околицю (рядок 74): одна товста смуга дає «пляму» сильних комірок |

Голоси рахує один `np.bincount` (рядок 51): кожну пару (ρ, θ) нумеруємо
числом `i_rho · n_theta + i_theta`. Відрізок малюємо від низу фото
(`y = H − 1`) до верху ROI.

**Чому θ від −90° до 90°, а не 0°…180°?** У 0°…180° майже вертикальна
смуга має два записи — біля 0° і біля 180° з протилежним ρ — і дає подвійні
піки.

### Спільні модулі

- **ROI** (`config.json → roi.polygon`): шестикутник дороги від 0,49 до
  0,72 висоти, капот відрізано — його відблиски давали хибні лінії. Разом з
  `min_angle_deg = 10` це підняло IoU p1 з 0,076 до 0,107, p2 з 0,064 до
  0,104 (на 100 фото). ROI накладаємо **після** виділення пікселів.
- **Маски** (`lanes/draw.py:20`): і знайдені, і еталонні смуги — лінії
  товщиною 16 px (`masks.thickness`), `ImageDraw.line`. Однакові правила
  малювання — чесне порівняння.
- **Раннер** (`lanes/runner.py`): для кожного фото й пайплайна зберігає
  стадії `NN_<стадія>.png`, `mask.png`, `overlay.png` і рядок у
  `metrics.csv`; упалий пайплайн чи битий файл не зупиняють прогін.
- **Вибірка** (`tools/make_sample.py`): з кожного списку CULane — кадри зі
  смугами з архівів `data.archives`, 20 випадкових з `seed = 42`.

## 2. Чому такий порядок стадій

**p1: колір → Собель → ROI → Хаф.** Колірна маска перша, бо Собелю по
всьому фото відповіли б краї машин, дерев, тіней. Собель після маски дає
лише межі плям фарби — тонкі лінії, що добре голосують у Хафі. Якщо
поміняти колір і Собеля місцями, маска кольору по контурах не має сенсу
(контур — це перепад, а не колір). ROI після Собеля: якби обрізати маску до
Собеля, межа ROI сама стала б контуром. Хаф останній — йому потрібна
бінарна маска.

**p2: вирівнювання → Оцу → Хаф.** Вирівнювання перше, бо Оцу краще ділить
контрастну гістограму; на темному кадрі всі яскравості стиснуті в малий
діапазон. Оцу після вирівнювання дає бінарну маску для Хафа. Якщо
поміняти місцями — вирівнювати бінарну маску безглуздо (лише два рівні).
Окремого виділення контурів у p2 немає — у Хаф іде вся пляма (це слабке
місце, див. розділ 5).

## 3. Метрики (`lanes/metrics.py`)

Порівнюємо дві маски 0/255 — еталон і знайдене.

```
MSE  = (1/N) · Σ (A − B)²                         (рядок 12)
PSNR = 10 · log10(255² / MSE),  MSE = 0 → 100 дБ  (рядок 18)
SSIM — вікно 7×7, середні через інтегральне зображення (рядки 30–44)
IoU  = |A ∩ B| / |A ∪ B|,  обидві порожні → 1     (рядок 76)
```

**Чому порожня маска має високий PSNR.** Для бінарних масок
`MSE = 255² · p`, де `p` — частка хибних пікселів, тож
`PSNR = 10 · log10(1 / p)`. Смуги займають ~3 % кадру; порожня маска
помиляється лише на них — 14,78 дБ. Кожна знайдена лінія, що не збіглася з
еталоном, додає хибні пікселі, тому PSNR будь-якого пайплайна нижчий, ніж у
p0. Поріг ТЗ PSNR ≥ 15 дБ — це не більше 3,2 % хибних пікселів.

**Навіщо p0.** Базова лінія «нічого не знайшли»: показує, що PSNR і SSIM
тут оманливі, а IoU — ні (у p0 він 0). Тому висновки робимо за IoU.

**Інтегральне зображення.** `S[y, x]` — сума всіх пікселів вище й лівіше;
сума будь-якого вікна — 4 звертання: `S[низ, право] − S[верх, право] −
S[низ, ліво] + S[верх, ліво]`. Так середні по всіх вікнах 7×7 — без циклу.

## 5. Обмеження й порівняння із сучасними підходами

- **p1 — фіксовані пороги.** Темний кадр — маска порожня; біле, що не фарба
  (машини, бордюри), — проходить. Покращення — адаптивний поріг кольору для
  кожного кадру, як у Chiu і Lin (2005).
- **p2 — найсвітліше не завжди фарба.** Фари, ліхтарі, сонячні плями; у Хаф
  іде вся пляма, тож велика пляма дає багато хибних голосів.
- **Лише прямі.** На повороті ближня частина смуги майже пряма, тож p1 там
  непоганий (0,213), але p3 з кривими кращий (0,249).
- **Нейромережі.** SCNN — F1 71,6 %, CLRNet (ResNet-18) — 79,58 % на CULane
  (смуга зарахована при IoU ≥ 0,5). Напряму з нашим IoU масок не
  порівнюється, але нейромережі «домальовують» закриті й стерті смуги, а ми
  бачимо лише те, що на пікселях. Наша перевага: без навчання, кожен крок
  пояснюється й змінюється одним параметром.

## 6. Двадцять ймовірних питань

1. **Що таке ядро Собеля?** Матриця 3×3, що рахує різницю правого й лівого
   стовпців (Gx) або нижнього й верхнього рядків (Gy); центр має вагу 2 —
   згладжування поперек похідної.
2. **Чим кореляція відрізняється від згортки?** Згортка перевертає ядро на
   180°. Для симетричних ядер (Гаус) однаково; для Собеля — змінюється знак,
   а модуль градієнта той самий.
3. **Чому HSV, а не RGB?** У RGB «білий» залежить від освітлення в усіх
   трьох каналах; у HSV яскравість — окремий канал V, а «без кольору» — мала
   S. Пороги прості й зрозумілі.
4. **Що буде з сірим пікселем у `rgb_to_hsv`?** δ = 0, тож H = 0 за
   домовленістю, S = 0; чорний — S = 0 (захист від ділення на нуль).
5. **Навіщо Собель у p1, якщо маска вже є?** Хаф по товстій плямі фарби дає
   багато голосів поперек смуги; межі плям — тонкі лінії вздовж смуги.
6. **Що таке гістограма й кумулятивна гістограма?** Скільки пікселів має
   кожен рівень; кумулятивна — скільки мають рівень ≤ v.
7. **Чому вирівнювання не зробило p2 кращим уночі?** Воно розтягує все,
   включно з фарами й ліхтарями, — вони стають найсвітлішими й Оцу відділяє
   саме їх.
8. **Що максимізує Оцу?** Міжкласову дисперсію `ω₀ω₁(μ₀ − μ₁)²` — це те
   саме, що мінімізувати дисперсію всередині класів.
9. **Навіщо дві ітерації Оцу?** Розмітка ~3 % кадру; перша ділить дорогу на
   темний і світлий асфальт, друга — світлий клас на асфальт і фарбу.
10. **Чому гістограма Оцу лише по ROI?** Небо й капот — великі площі, які
    зсунули б поріг, хоча смуг там немає.
11. **Чому пряма задана (ρ, θ), а не y = kx + b?** Вертикальна пряма має
    нескінченний k; ρ і θ обмежені для будь-якої прямої (Duda, Hart, 1972).
12. **Навіщо придушення околиці піка?** Одна товста смуга дає кілька сильних
    сусідніх комірок — без придушення це були б 4 майже однакові лінії.
13. **Чому `min_angle_deg = 10`, а не 20?** Еталонні смуги пологі (медіана
    26°, чверть менше 14°); при 20° бічні смуги не голосували. Ціна — більше
    хибних пологих ліній від тіней.
14. **Чому ROI накладаємо після Собеля, а не до?** Інакше межа ROI — різкий
    перепад 0→255 — сама стала б контуром і дала хибну пряму.
15. **Звідки 16 пікселів товщини маски?** Рішення ADR-0004. Еталон CULane —
    лише точки центру смуги, тож маску треба намалювати лінією якоїсь
    товщини. Лінія в 1 px дала б IoU ≈ 0 навіть при зсуві на 2 px; занадто
    товста (50+ px) зливала б сусідні смуги. 16 px — компроміс, однаковий для
    еталону й результату (маски будує раннер, ADR-0005).
16. **Чому PSNR порожньої маски вищий, ніж у пайплайнів?** Див. розділ 3:
    PSNR рахує лише частку хибних пікселів, а смуги — 3 % кадру.
17. **Чому не медіанний фільтр перед Оцу?** Можна (прибрав би дрібний шум),
    але не в ТЗ; основна помилка p2 — великі світлі плями, а медіанний
    фільтр їх не прибирає.
18. **Що буде на повороті?** Хаф дає прямі; ближня частина повороту майже
    пряма, тож p1 знаходить її (0,213), але далека частина смуги — мимо.
19. **Що буде з фото 1×1 чи однотонним?** Вирівнювання повертає без змін,
    Оцу — поріг = це значення, маска порожня, Хаф — 0 ліній
    (`tests/test_edge_cases.py`).
20. **Як ви підбирали параметри й чи не підігнали під вибірку?** Підбір на
    20 фото (кожне п'яте), перевірка на інших 80: IoU p1 0,131, p2 0,095 —
    близько до 0,138 і 0,104 на всіх 100.

## 7. Мікрозавдання

**Змінити параметр** — лише `config.json`. Наприклад, `p1.white_v_min` з
0,55 на 0,45 або `p2.otsu_iterations` з 2 на 1. Перевірка:

```bash
python -m pytest tests/test_p1_color.py tests/test_p2_otsu.py
python main.py run --pipeline p1 --limit 10
python main.py check
```

**Додати стадію** — наприклад, гаусове розмиття перед вирівнюванням у p2:

1. `lanes/pipelines/p2_otsu.py` — імпорти
   `from lanes.filters import apply_kernel` і
   `from lanes.methods.canny import gaussian_kernel`;
2. рядок 24 замінити на
   `blurred = apply_kernel(rgb_to_gray(image), gaussian_kernel(5, 1.4))` і
   `equalized = equalize_histogram(blurred)`;
3. додати `("blurred", blurred)` першим у список `stages` (рядок 35);
4. оновити таблицю p2 у `docs/pipelines.md` і список стадій у
   `tests/test_p2_otsu.py` та `tests/test_edge_cases.py`.

**Замінити метод** — Собель → Прюітт у p1:

1. `lanes/pipelines/p1_color.py` — замість
   `from lanes.methods.sobel import sobel_magnitude` взяти
   `from lanes.methods.prewitt import prewitt_magnitude`;
2. рядок 29: `magnitude = prewitt_magnitude(mask * 255.0)`.

Контракт той самий (`np.float64 (H, W)`), решта стадій не змінюється.
Після будь-якої зміни:

```bash
python -m pytest
python -m pylint lanes tools tests main.py
```
