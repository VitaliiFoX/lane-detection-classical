# Специфікація пайплайнів

Чотири пайплайни, погоджені з викладачкою. Кожен має 3 стадії з 3 різних
категорій методів, і всі 4 відрізняються комбінацією категорій. Ця специфікація
— контракт: реалізуй саме її, а якщо в процесі виявиться, що щось не працює,
спершу зміни цей документ (і, за потреби, `ADR.md`), а потім код.

| № | Назва | Власник | Стадії | Категорії |
|---|---|---|---|---|
| p1 | Колір | Фояк Віталій | HSV-маска білого й жовтого → фільтр Собеля → перетворення Хафа | колірна корекція · контурний аналіз · перетворення Хафа |
| p2 | Оцу | Фояк Віталій | вирівнювання гістограми → поріг Оцу → перетворення Хафа | гістограмна корекція · сегментація · перетворення Хафа |
| p3 | Вид зверху | Сивопляс Максим | перспективне перетворення → фільтр Прюітта → гістограма стовпців із ковзними вікнами | геометричні перетворення · фільтрація · гістограмний аналіз |
| p4 | Top-hat | Сивопляс Максим | морфологічний top-hat → метод Кенні → перетворення Хафа | морфологія · контурний аналіз · перетворення Хафа |

`p0` — базова лінія без обробки: повертає нуль смуг. Потрібна, щоб показати,
який PSNR дає порожня маска (див. `docs/metrics.md`).

## Спільний контракт

```python
def run(image: np.ndarray, config: dict) -> PipelineResult
```

- `image` — фото `np.uint8 (H, W, 3)` RGB будь-якого розміру, також 1×1.
- `config` — увесь `config.json`; пайплайн сам бере свою секцію
  (`config["p1"]`…`config["p4"]`) і спільні `config["roi"]`, `config["hough"]`
  та передає методам окремі числа аргументами.
- Повертає `PipelineResult(stages, lanes)`:
  - `stages` — список `(назва, масив)` проміжних результатів у порядку стадій;
    раннер збереже їх як `01_<назва>.png`, `02_…`;
  - `lanes` — список знайдених смуг, кожна `np.ndarray (N, 2)` точок `(x, y)`
    у координатах вхідного фото.
- Маску смуг для метрик і картинку з лініями поверх фото робить раннер, не
  пайплайн.
- Пайплайн не читає файли, не друкує й не падає на однотонному чи крихітному
  фото — повертає порожній список смуг.

### Область інтересу (`roi`, спільна, `lanes/roi.py`)

Трапеція перед капотом, вершини задано частками ширини й висоти:
`roi.polygon = [[x0, y0], …]`, точка `[0.5, 1.0]` — середина нижнього краю.
Верхня межа трапеції (`min y`) — це також рівень, до якого Хаф продовжує
знайдені лінії. p1, p2 і p4 застосовують ROI до бінарної маски **після**
виділення контурів (щоб межа трапеції не дала хибного контуру). p3 замість ROI
використовує свою трапецію перспективного перетворення.

### Перетворення Хафа (спільне, `lanes/methods/hough.py`, власник Фояк)

Вхід — бінарна маска контурів. Параметри — секція `hough`.

1. Кути нормалі θ від −90° до 90° (не включно) з кроком `theta_step_deg`:
   θ = 0° — вертикальна лінія, θ = ±90° — горизонтальна. Діапазон 0°…180°
   не беремо, бо там майже вертикальна смуга має два записи (біля 0° і біля
   180°) і дає подвійні піки. Лишаємо тільки ті θ, для яких кут лінії до
   горизонталі `α = 90° − |θ|` не менший за `min_angle_deg`: смуги на фото
   круті, а горизонтальні лінії — це тіні, бампери, стоп-лінії.
2. Для кожного білого пікселя `(x, y)` і кожного θ:
   `ρ = x·cos θ + y·sin θ`; індекс `round((ρ + D) / rho_step)`, де
   `D = ceil(sqrt(W² + H²))`. Голоси — `np.bincount` в акумулятор
   `(n_rho, n_theta)`.
3. Піки: до `max_lanes` разів беремо максимум акумулятора; якщо голосів менше
   за `min_votes` — зупиняємось; інакше записуємо `(ρ, θ)` і обнуляємо
   околицю `± suppress_rho` пікселів і `± suppress_theta_deg` градусів.
4. Кожен пік перетворюємо на відрізок від нижнього краю фото `y = H − 1` до
   верху ROI `y_top`: `x = (ρ − y·sin θ) / cos θ`.
5. Повертаємо `(lanes, accumulator)`; акумулятор, нормований до 0…255,
   пайплайн додає до `stages` як `hough_space` — це гарна картинка для звіту.

## p1 «Колір» (Фояк Віталій)

| Стадія | Метод | Що зберігаємо |
|---|---|---|
| 1 | `color.rgb_to_hsv` → `color.white_yellow_mask` | `hsv_mask` |
| 2 | `sobel.sobel_magnitude` по масці як `0/255`, поріг `sobel_threshold · max`, потім `& roi` | `sobel_magnitude`, `edges_roi` |
| 3 | `hough.detect_lanes` | `hough_space` |

HSV вручну: `V = max(R,G,B)/255`; `S = (max − min)/max` (0, якщо `max = 0`);
`H` у градусах 0…360 за стандартною формулою за тим, який канал максимальний.
Білий: `S ≤ white_s_max` і `V ≥ white_v_min`. Жовтий:
`yellow_h_min ≤ H ≤ yellow_h_max`, `S ≥ yellow_s_min`, `V ≥ yellow_v_min`.

Очікування: найкраще вдень, гірше вночі й у тіні (білий стає сірим).

## p2 «Оцу» (Фояк Віталій)

| Стадія | Метод | Що зберігаємо |
|---|---|---|
| 1 | `color.rgb_to_gray` → `histogram.equalize_histogram` | `equalized` |
| 2 | `threshold.otsu_binarize` по пікселях ROI, `otsu_iterations` разів, потім `& roi` | `otsu` |
| 3 | `hough.detect_lanes` | `hough_space` |

Сіре: `Y = 0.299·R + 0.587·G + 0.114·B`.

Вирівнювання: гістограма 256 рівнів (`np.bincount` по округленому сірому),
кумулятивна `cdf`, нове значення
`round((cdf(v) − cdf_min) / (N − cdf_min) · 255)`; якщо всі пікселі однакові
— повертаємо фото без змін.

Оцу: для кожного порогу `t` міжкласова дисперсія
`σ²_B(t) = ω₀(t)·ω₁(t)·(μ₀(t) − μ₁(t))²`; беремо `t` з максимумом. Пікселі
`> t` — білі. **Ітеративно**: розмітка займає кілька відсотків кадру, тому
один поріг Оцу ділить дорогу навпіл. Тож кожну наступну ітерацію рахуємо лише
по пікселях, яскравіших за попередній поріг (`otsu_iterations`, за
замовчуванням 2). Порогові значення кожної ітерації повертаємо — вони йдуть у
звіт.

Очікування: стійкіше вночі (вирівнювання підтягує контраст), але більше хибних
ділянок від яскравих машин і світла фар.

## p3 «Вид зверху» (Сивопляс Максим)

| Стадія | Метод | Що зберігаємо |
|---|---|---|
| 1 | `color.rgb_to_gray` → `perspective.homography` + `perspective.warp` | `top_view` |
| 2 | `prewitt.prewitt_magnitude`, поріг `prewitt_threshold · max` | `prewitt_magnitude`, `edges` |
| 3 | `sliding_windows.detect_lanes_top_view` → `perspective.transform_points` назад у фото | `windows` |

Перспектива: `src` — чотири точки трапеції на фото (частки ширини й висоти, у
порядку верх-ліво, верх-право, низ-право, низ-ліво), `dst` — прямокутник
`warp_size = [ширина, висота]` з відступом `warp_margin` (частка ширини)
зліва й справа. Матрицю 3×3 знаходимо з 8 рівнянь
(`np.linalg.solve`, `h33 = 1`). Деформацію робимо **зворотним відображенням**:
для кожного пікселя результату рахуємо координату у фото через обернену
матрицю й беремо найближчий піксель (поза фото — 0).

Ковзні вікна:

1. Гістограма стовпців — кількість білих пікселів у кожному стовпці нижньої
   половини виду зверху.
2. Стартові точки — до `max_lanes` піків гістограми з відстанню не менше
   `peak_min_distance` і висотою не менше `min_pixels`.
3. Для кожної стартової точки йдемо знизу вгору `n_windows` вікнами ширини
   `2 · window_margin`; білі пікселі у вікні додаємо до смуги; якщо їх більше
   за `min_pixels` — центр наступного вікна зсуваємо на їхнє середнє `x`.
4. Через зібрані пікселі проводимо параболу `x = a·y² + b·y + c`
   (`np.polyfit`, ступінь `poly_degree`), беремо точки на `n_windows + 1`
   рівнях `y` і переводимо їх у координати фото оберненою матрицею.

Зображення `windows` — контури виду зверху з намальованими вікнами й
параболами (через `ImageDraw`).

Очікування: єдиний пайплайн, що повертає криві, а не прямі, тож має виграти
на поворотах. Слабке місце — фіксована трапеція: на підйомах і спусках вона
«з'їжджає».

## p4 «Top-hat» (Сивопляс Максим)

| Стадія | Метод | Що зберігаємо |
|---|---|---|
| 1 | `color.rgb_to_gray` → `morphology.top_hat` з горизонтальним елементом `1 × tophat_width` | `tophat` |
| 2 | `canny.canny` з `canny_kernel`, `canny_sigma`, `canny_low`, `canny_high`, потім `& roi` | `canny`, `edges_roi` |
| 3 | `hough.detect_lanes` | `hough_space` |

Top-hat: `opening = dilate(erode(gray))`, `top_hat = gray − opening`. Ерозія —
мінімум у вікні, дилатація — максимум. Горизонтальний елемент ширший за
смугу «стирає» вузькі світлі смуги з відкриття, тож у різниці лишаються саме
вони, а широкі світлі об'єкти (небо, машини) зникають.

Кенні:

1. Гаусове ядро `canny_kernel × canny_kernel` з `canny_sigma`, нормоване до
   суми 1, через `filters.apply_kernel`.
2. Градієнти — `sobel.sobel_gradients` (модуль Фояка, ADR-0010), модуль
   `hypot(gx, gy)` і напрям `atan2(gy, gx)`.
3. Потоншення: напрям округлюємо до 0°, 45°, 90°, 135°; піксель лишаємо, якщо
   він не менший за двох сусідів уздовж градієнта.
4. Подвійний поріг: сильні `≥ canny_high · max`, слабкі `≥ canny_low · max`.
5. Гістерезис: слабкий піксель стає контуром, якщо пов'язаний (8 сусідів)
   із сильним; повторюємо поширення, доки маска змінюється.

Очікування: стійкий до тіней (top-hat прибирає повільні зміни яскравості),
але чутливий до шуму асфальту й тріщин.

## Параметри (`config.json`)

| Ключ | За замовчуванням | Зміст |
|---|---|---|
| `seed` | 42 | вибір фото й синтетичний шум |
| `roi.polygon` | трапеція | вершини ROI, частки `(x/W, y/H)` |
| `masks.thickness` | 16 | товщина ліній у масках для метрик, px |
| `hough.rho_step` | 1 | крок ρ, px |
| `hough.theta_step_deg` | 1 | крок θ, ° |
| `hough.min_angle_deg` | 20 | мінімальний кут лінії до горизонталі, ° |
| `hough.max_lanes` | 4 | максимум смуг (CULane розмічає до 4) |
| `hough.min_votes` | 40 | мінімум голосів піка |
| `hough.suppress_rho` | 20 | придушення околиці піка по ρ, px |
| `hough.suppress_theta_deg` | 5 | придушення околиці піка по θ, ° |
| `p1.white_s_max`, `p1.white_v_min` | 0.20, 0.75 | поріг білого |
| `p1.yellow_h_min`, `p1.yellow_h_max` | 35, 65 | відтінок жовтого, ° |
| `p1.yellow_s_min`, `p1.yellow_v_min` | 0.35, 0.50 | насиченість і яскравість жовтого |
| `p1.sobel_threshold` | 0.30 | частка максимуму модуля Собеля |
| `p2.otsu_iterations` | 2 | кількість ітерацій Оцу |
| `p3.src` | трапеція | вершини для виду зверху, частки |
| `p3.warp_size` | [400, 600] | ширина й висота виду зверху, px |
| `p3.warp_margin` | 0.25 | відступ прямокутника `dst` зліва й справа, частка |
| `p3.prewitt_threshold` | 0.30 | частка максимуму модуля Прюітта |
| `p3.max_lanes`, `p3.peak_min_distance` | 4, 60 | стартові піки гістограми |
| `p3.n_windows`, `p3.window_margin`, `p3.min_pixels` | 10, 40, 30 | ковзні вікна |
| `p3.poly_degree` | 2 | ступінь кривої |
| `p4.tophat_width` | 31 | ширина структурного елемента, px |
| `p4.canny_kernel`, `p4.canny_sigma` | 5, 1.4 | гаусове згладжування в Кенні |
| `p4.canny_low`, `p4.canny_high` | 0.10, 0.30 | частки максимуму градієнта |

Значення за замовчуванням — стартові. Підбираємо їх у пілотному запуску
(задача T1) і пояснюємо вибір у звіті.
