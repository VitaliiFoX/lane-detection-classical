# Архітектура

Як влаштована програма, які в неї модулі та якими даними вони обмінюються.
Чому зроблено саме так — [ADR.md](ADR.md). Що саме рахує кожен пайплайн —
[docs/pipelines.md](docs/pipelines.md).

## 1. Шари

```
                 ┌────────────────────────────────────┐
                 │  main.py  (run · report · check)   │   командний рядок, без логіки
                 └─────────────────┬──────────────────┘
                                   ▼
   ┌───────────────────────────────────────────────────────────────┐
   │  lanes/runner.py · lanes/checks.py · lanes/report.py          │   оркестрація:
   │  цикл по вибірці, збереження стадій, метрики, CSV, графіки    │   файли й таблиці
   └───────┬───────────────────────┬───────────────────────────────┘
           ▼                       ▼
   ┌───────────────────┐   ┌──────────────────────────────────────┐
   │ lanes/pipelines/  │──▶│ lanes/methods/                        │   алгоритми:
   │ p0 … p4           │   │ color, histogram, threshold, sobel,   │   чисті функції
   │ послідовність     │   │ hough, prewitt, morphology, canny,    │   над масивами
   │ стадій            │   │ perspective, sliding_windows          │
   └───────────────────┘   └──────────────────┬───────────────────┘
                                              ▼
   ┌───────────────────────────────────────────────────────────────┐
   │ lanes/filters.py (apply_kernel) · lanes/roi.py                │   спільні примітиви
   │ lanes/io_utils.py · lanes/draw.py · lanes/metrics.py          │
   │ lanes/synthetic.py · lanes/config.py                          │
   └───────────────────────────────────────────────────────────────┘
```

**Правило залежностей:** стрілки — лише вниз. Методи не знають про файли,
конфігурацію й пайплайни; пайплайни не знають про файли й CSV. Тому кожен
метод тестується на масиві 3×3, а кожен пайплайн — на синтетичному кадрі,
без вибірки.

## 2. Модулі

| Модуль | Власник | Що робить |
|---|---|---|
| `main.py` | Фояк | розбір аргументів, виклик `runner` / `report` / `checks` |
| `lanes/config.py` | Фояк | читання `config.json` |
| `lanes/io_utils.py` | Фояк | читання фото й розмітки `.lines.txt`, збереження PNG |
| `lanes/filters.py` | Фояк | `apply_kernel` — ручна кореляція з ядром |
| `lanes/draw.py` | Фояк | маска смуг заданої товщини, фото з лініями |
| `lanes/metrics.py` | Фояк | MSE, PSNR, SSIM, IoU |
| `lanes/runner.py` | Фояк | обробка вибірки, збереження стадій, `metrics.csv` |
| `lanes/roi.py` | Максим | трапеція області інтересу |
| `lanes/synthetic.py` | Максим | синтетичний кадр дороги з відомими смугами |
| `lanes/checks.py` | Максим | відхилення смуг, еталонні сценарії C1 |
| `lanes/report.py` | Максим | `summary.csv`, графіки для звіту |
| `lanes/methods/*` | за файлом | див. `lanes/methods/README.md` |
| `lanes/pipelines/*` | за файлом | див. `lanes/pipelines/README.md` |

## 3. Контракти даних

| Що | Тип | Форма і діапазон |
|---|---|---|
| кольорове фото | `np.uint8` | `(H, W, 3)`, RGB, 0…255 |
| сіре фото, модуль градієнта | `np.float64` | `(H, W)`, сіре 0…255 |
| бінарна маска | `np.bool_` | `(H, W)` |
| маска для метрик | `np.uint8` | `(H, W)`, значення 0 або 255 |
| смуга | `np.float64` | `(N, 2)`, точки `(x, y)` у пікселях фото, `N ≥ 2` |
| список смуг | `list[np.ndarray]` | може бути порожнім |
| результат пайплайна | `PipelineResult` | `stages: list[tuple[str, np.ndarray]]`, `lanes: list[np.ndarray]` |

`io_utils.save_png` вміє зберегти будь-який із цих масивів: маску — як 0/255,
дійсні числа — нормує до 0…255.

## 4. Потік `main.py run`

```
config.json ──▶ load_config
data/sample.csv ──▶ для кожного фото:
    load_rgb(jpg) ─┬─▶ pipeline.run(image, config) ─▶ stages, lanes
                   │                                     │
    read_lanes(txt)┴─▶ lanes_mask(gt)   lanes_mask(lanes)◀┘
                          │                   │
                          └──▶ mse/psnr/ssim/iou ──▶ рядок metrics.csv
    save_png: results/<pipeline>/<group>/<фото>/01_<стадія>.png … mask.png, overlay.png
```

Пайплайн, що впав на фото, не зупиняє прогін: раннер пише рядок з порожніми
метриками й повідомлення в консоль. Битий файл фото — те саме
(`ImageLoadError`).

## 5. Як розширювати (типові мікрозавдання на захисті)

**Змінити параметр.** Лише `config.json`, код не чіпаємо.

**Додати метод.** Новий файл у `lanes/methods/`, чиста функція з
докстрінгом, тест 3×3 з ручним розрахунком у `tests/test_<метод>.py`,
рядок у таблиці `lanes/methods/README.md`.

**Додати стадію в пайплайн.** У функції `run` пайплайна викликати метод між
сусідніми стадіями й додати `(назва, результат)` у `stages`; нові параметри
— у секцію пайплайна в `config.json` і в таблицю `docs/pipelines.md`.

**Замінити метод.** Те саме, але замість старого виклику; контракт масивів
(розділ 3) гарантує, що сусідні стадії не зламаються, якщо новий метод
повертає той самий тип.

**Додати пайплайн.** Файл `lanes/pipelines/pN_<назва>.py` з функцією `run`,
рядок у `REGISTRY` у `lanes/pipelines/__init__.py`, секція в `config.json`.
Раннер, звіт і перевірки підхоплять його автоматично.
