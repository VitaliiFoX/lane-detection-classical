# Наступна задача з PLAN.md

Ти працюєш у командному STEM-проєкті. Правила — `AGENTS.md` (корінь і теки);
дотримуйся їх буквально, особливо «Жорстких правил».

## 1. Хто працює

Визнач учасника за `git config user.name` і `git config user.email` та
таблицею «Учасники» на початку `PLAN.md` (префікс `F` — Фояк Віталій, `M` —
Сивопляс Максим). Якщо не збігається жоден варіант — спитай людину один раз
і далі в сесії не питай.

## 2. Яка задача

1. `git pull --rebase` (якщо є віддалений репозиторій). Конфлікт — зупинись і
   покажи людині.
2. Якщо людина назвала номер задачі — бери її. Інакше в розділі свого
   учасника знайди першу задачу з `[ ]`, у якої всі задачі зі стовпця
   «Після» вже `[x]`. Задачі `T` — лише якщо людина попросила.
3. Немає доступної задачі — скажи, які задачі чекають і на що (на чию
   задачу), і запропонуй, що можна зробити паралельно (наприклад, тести чи
   документацію своєї наступної задачі). Нічого не починай без відповіді.
4. Скажи людині одним рядком: «Беру <номер>: <назва>».

## 3. Виконання

1. Прочитай специфікацію: `docs/pipelines.md`, `docs/metrics.md` або
   `docs/data.md` — що стосується задачі; `AGENTS.md` теки файлу.
2. Реалізуй функції в заготовці свого файлу. Сигнатури не змінюй. Пиши
   просто й явно — людина захищатиме кожен рядок; докстрінг з формулою,
   коментар до кожного нетривіального кроку.
3. Тести за `tests/AGENTS.md`: ручний розрахунок 3×3/5×5 з коментарем +
   крайній випадок. Для пайплайна — синтетичний кадр.
4. Запусти, з інтерпретатором `.venv` (`.venv/bin/python` або
   `.venv\Scripts\python.exe`):
   - `python -m pytest`
   - `python -m pylint lanes tools tests main.py` — 10.00/10, без
     повідомлень.
   Падає чуже — не виправляй чужий файл, скажи людині, чий він.
5. Критерій «Готово, коли» з `PLAN.md` виконано буквально? Якщо ні —
   продовжуй або поясни, що заважає.

## 4. Завершення

1. Познач задачу `[x]` у `PLAN.md`. Якщо закрито етап — онови таблицю
   «Статус» у `README.md`.
2. Додай рядок у `META-USAGE.md`: дата, учасник, «Claude Code (<модель>)»,
   задача, ключовий запит людини, що згенеровано, що людина має перевірити.
   Останній стовпець заповнюй як «потребує перевірки автором», якщо людина
   не переглядала код.
3. Коміт від імені людини, одна задача — один коміт, Conventional Commits
   українською з номером задачі: `feat: фільтр Собеля (F7)`. Людина вже
   попросила виконати задачу — це дозвіл на локальний коміт. `git push` —
   лише якщо людина дозволила.
4. Відповідь людині, коротко:
   - що зроблено і де (файли);
   - **3–5 речень «як пояснити на захисті»**: ідея методу, формула, чому
     такі параметри;
   - результат тестів і pylint;
   - яка задача наступна і чи доступна вона.

Після цього не бери наступну задачу сам: людина має переглянути код і
зрозуміти його. Продовжуй, лише якщо людина сказала працювати далі або
одразу назвала кілька задач.
